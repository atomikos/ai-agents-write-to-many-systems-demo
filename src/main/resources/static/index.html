How it works

refund(refundId, orderId)
① record the intent → PostgreSQL · saga row PENDING
② add the refund note → CRM over HTTP, idempotency key = refundId
③ mark the order refunded, saga row COMPLETED → PostgreSQL
④ publish RefundIssued → Artemis · queue "refund.events"
⑤ request the confirmation email → Artemis · queue "email.requests"
Dashed box = one XA transaction: all three commit together, or none does.
↓  only after commit
BillingListener books the refund · EmailSender sends the email

The CRM cannot join the transaction. If anything fails after step ②, the compensator reverts the note by its key; after a crash, a sweep does the same once the refund has been PENDING for 30 seconds.
